# Interface design: research, principles, mockups (2026-11-05, lane `ui-design`)

## Brief

- **Asked** (Ludovic's words): "use state of the art design concept and prepare some mockup for the overall interface
  (like untold story, and molstar v6 prism approach). Do some research, evaluate our context and all the data we are
  dealing with. The UI should be easy to find and always make sense, and be consistent." ("untold story" is read as
  MolViewStories, molstar.org/mol-view-stories; confirm in the PR.) **Check:** Ludovic opens the mockups in a browser
  (static HTML, no build), in light and dark, walks the main tasks through them, and finds every existing feature in
  the new layout; the design doc says why each choice was made.
- **Spec:** new `web/_spec/design/` (the design spec: research, context, principles, information architecture, the
  design system), linked from `web/_spec/README.md`'s table. No code spec changes.
- **Research, cited** (sources with URLs, each finding tied to a decision):
  - Mol\* v6 Prism: `~/Developments/molstar/packages/prism/ui/_spec/` (shell, styling, commands, accessibility,
    library, view-models), `packages/prism/viewer/_spec/` (README, parity.md), `.v6/designs/summary.md`; run or read
    its storybook/stories if useful.
  - MolViewStories: `~/Developments/mol-view-stories` (its UI code and docs) and molstar.org/mol-view-stories.
  - State of the art on the web: scientific and creative tools with dense data and a 3D view (e.g. Mesoscale Explorer,
    Allen cellPACK/Simularium, ChimeraX, BioRender, Figma, Blender, Linear, Nomad-style inspectors): command palette,
    selection → inspector, progressive disclosure, task-based workspaces, one selection model across views, empty
    states, keyboard and accessibility (WCAG 2.2). Use WebSearch/WebFetch; do not cite from memory.
- **Our context, from the code** (read, don't guess): the data model (`web/src/domain/recipe/types.ts`, parsers,
  `SKILLS.md` at the repo root, `data/*.json` examples incl. the largest, `data/Mpn_1.0_2.json`): recipe → compartments
  → surface/interior ingredients, fibers, interactions, every property (count, molarity, MW, pdb, uniprot, geometry,
  beads/LOD, orientation, offset, colour, custom columns), sizes from 5 to hundreds of ingredients; the user tasks
  (create a recipe, curate and validate it, LLM-generated recipes through Skills, find and assign structures, orient an
  ingredient on a membrane or fiber, build beads, see the whole packed scene, export for cellPACK/cellPAINT); every
  current panel and menu item (`web/src/components/layout/menuConfig.ts`, `Workspace.tsx`, presets), and
  `web/_spec/parity.md` (incl. what is still missing: whole-scene viewer, URL loading, Help/Settings pages).
- **Deliverables:**
  1. `web/_spec/design/README.md`: research findings (cited), our context (data, users, tasks), 6-10 principles (rule +
     reason + where it shows), the information architecture (the object model → where each object is seen, selected,
     edited; one selection shared by every view), navigation (workspaces/tasks, command palette, menus), the design
     system (tokens: colour incl. depth and data palettes, type, spacing, density; components; states; light/dark;
     accessibility), and a **coverage table**: every current menu item, panel and control → where it lives in the new
     design (nothing lost; anything dropped says why).
  2. `web/design/mockups/`: self-contained static HTML/CSS (no build, no network; inline SVG for the 3D and recipe
     views — the Recipe view drawn as legacy's circle packing, see `web/_spec/recipe-view.md` §2 and
     `web/tests/fixtures/recipe-view-oracle/legacy-hiv.png` on `origin/lane/recipe-view-canvas`), one shared
     `tokens.css`, an `index.html` linking the screens. Screens: the overall shell; recipe build and curate (Recipe
     view + table + inspector); ingredient focus (protein, membrane/fiber orientation, beads); the whole scene (Mol\*
     v6); find and assign a structure (PDB/UniProt/AlphaFold search); load/import incl. the LLM Skills flow; the empty
     first-run state; the command palette. Each in light and dark, real data from HIV or Mpn (names, counts).
  3. PNG screenshots of each screen (light and dark) at 1440×900, taken with Playwright from `file://`, in
     `web/design/mockups/screenshots/`.
- **Tests:** none for code (no `src/` change). Checks: every mockup opens from `file://` with no console errors and no
  network request (a small Playwright script in `web/design/mockups/check.mjs`); the coverage table has a row for every
  `menuConfig.ts` leaf and every `Workspace.tsx` panel (the script or a reviewer checks it).
- **Touches:** `web/_spec/design/`, `web/design/`, one row in `web/_spec/README.md`. **Stays off:** everything under
  `web/src/` and `web/tests/` (lane `recipe-view-canvas` is in flight there), `CLAUDE.md`, `web/progress/current.md`.
- **Size:** no production code; ~600-900 lines of design doc, ~8 mockup screens.
- **Steps and models:** 1. research Prism, MolViewStories and the web (Opus, with Sonnet subagents for fetching and
  summarising sources) 2. our context from the code (Sonnet inventory, Opus synthesis) 3. principles, IA, design system
  (Opus) 4. mockups (Opus authors; Sonnet for screenshots and the check script) 5. gate: reviewer and skeptic (Opus) on
  coverage, consistency between screens, and claims vs sources.
- **Ports:** none (mockups from `file://`).
